## 2024-06-02 - [FFmpeg Memory Allocation and Copy Overhead]
**Learning:** In the current recording pipeline, raw video frames are encoded by the `HardwareEncoder` into an `AVPacket`, copied into an `EncodedPacket` with `std::vector<uint8_t>`, and then copied again into a `WriteTask` (`std::vector<uint8_t>`) before being placed in a `std::queue<WriteTask>` for the `DiskWriter` thread. The `DiskWriter` thread then allocates a new `AVPacket` and copies the data into it one last time to write to disk. This implies two large memory allocations and three massive byte copies per frame in a tight 60fps loop, introducing latency and increasing CPU/memory usage.
**Action:** Use FFmpeg's `av_packet_move_ref` and `std::shared_ptr<AVPacket>` with a custom deleter (`[](AVPacket* p) { av_packet_free(&p); }`) to eliminate byte copies entirely and allow `DiskWriter` to write the packet exactly as output by `HardwareEncoder`.
